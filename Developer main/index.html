What is Git?

Git is a version control system that tracks changes in your code over time. You can go back to any previous state, collaborate with others, and avoid losing work.

GitHub is a website that hosts Git repositories online so you and your team can access them from anywhere.

Why use Git?

  1. Track changes — Every save (commit) records what changed and why.
  2. Collaborate — Multiple people can work on the same project safely.
  3. Revert anytime — Made a mistake? Roll back to a working version instantly.
  4. Branch & merge — Experiment in isolation without breaking the main code.

Installation & Setup

Install Git

Windows: Download from git-scm.com and run the installer.

macOS: Run in Terminal:

xcode-select --install

Or via Homebrew:

brew install git

Linux (Ubuntu/Debian):

sudo apt update && sudo apt install git

First-time Configuration

Tell Git who you are — this info appears on every commit:

git config --global user.name  "Your Name"
git config --global user.email "you@example.com"
git config --global core.editor "code --wait"

Verify your config:

git config --list

Basic Commands

Initialize a repository

mkdir my-project
cd my-project
git init

The Three Stages of Git

Stage What it means Command to move forward
Working Directory Files you are editing right now git add <file>
Staging Area Files queued up for the next save git commit -m "msg"
Repository Saved history stored by Git —

Track, Stage, and Commit

git status               <!-- Check what changed -->
git add index.html       <!-- Stage a specific file -->
git add .                <!-- Stage all changes -->
git commit -m "Add homepage layout"

View History

git log
git log --oneline
git diff index.html

Tip: Write commit messages in the present tense — e.g. "Add login form" not "Added login form".

Branching & Merging

A branch is an independent copy of your code. Work on a feature in a branch; merge it back when ready.

git branch                        <!-- List all branches -->
git checkout -b feature/login     <!-- Create and switch to new branch -->
git checkout main                 <!-- Switch back to main -->
git merge feature/login           <!-- Merge branch into main -->
git branch -d feature/login       <!-- Delete branch after merging -->

Warning: If Git says "merge conflict", two branches changed the same line. Open the file, pick which version to keep, then git add and git commit to finish.

Working with GitHub

Push an existing repo to GitHub

git remote add origin https://github.com/yourname/repo.git
git push -u origin main

Clone an existing repo

git clone https://github.com/yourname/repo.git
cd repo

Keep your local code up to date

git pull origin main

The Standard Workflow

  1. Pull latest — git pull origin main
  2. Create a branch — git checkout -b feature/x
  3. Write code and commit — git add . && git commit -m "..."
  4. Push the branch — git push origin feature/x
  5. Open a Pull Request on GitHub and get it reviewed
  6. Merge on GitHub and delete the branch
