What is Git?

Git is a version control system — it tracks changes in your code over time so you can go back to any previous state, collaborate with others, and avoid losing work.

GitHub is a website that hosts Git repositories online so you (and your team) can access them from anywhere.

1

Track changes

Every save (commit) records what changed and why.

2

Collaborate

Multiple people can work on the same project safely.

3

Revert anytime

Made a mistake? Roll back to a working version instantly.

4

Branch & merge

Experiment in isolation without breaking the main code.

Installation & Setup

Install Git

Windows: Download from git-scm.com and run the installer.

macOS: Run xcode-select --install in Terminal, or via Homebrew: brew install git

Linux (Ubuntu/Debian):

sudo apt update && sudo apt install git

First-time configuration

Tell Git who you are — this info appears on every commit:

git config --global user.name  "Your Name"
git config --global user.email "you@example.com"
git config --global core.editor "code --wait"  # VS Code as editor

Verify your config:

git config --list

Basic Commands

Initialize a repository

# Create a new folder and open it
mkdir my-project && cd my-project

# Initialize Git inside it
git init

The three stages of Git

Understanding this is the most important concept in Git:

StageWhat it meansCommand to move forward
Working DirectoryFiles you're editing right nowgit add <file>
Staging AreaFiles queued up for the next savegit commit -m "msg"
RepositorySaved history stored by Git—

Track, stage, and commit

# Check what's changed
git status

# Stage a specific file
git add index.html

# Stage all changed files
git add .

# Commit with a message
git commit -m "Add homepage layout"

View history

# Full history
git log

# Short one-line history
git log --oneline

# See what changed in a file
git diff index.html
Write commit messages in the present tense — e.g. "Add login form" not "Added login form".

Branching & Merging

A branch is an independent copy of your code. Work on a feature in a branch; merge it back when ready.

# List all branches (current shown with *)
git branch

# Create and switch to a new branch
git checkout -b feature/login

# Switch back to main
git checkout main

# Merge your branch into main
git merge feature/login

# Delete branch after merging
git branch -d feature/login
If Git says "merge conflict", two branches changed the same line. Open the file, pick which version to keep, then git add and git commit to finish.

Working with GitHub

Push an existing repo to GitHub

# Add GitHub as the remote
git remote add origin https://github.com/yourname/repo.git

# Push your code
git push -u origin main

Clone an existing repo

git clone https://github.com/yourname/repo.git
cd repo

Keep your local code up to date

# Pull latest changes from GitHub
git pull origin main

The Standard Workflow

Every professional team follows roughly this loop:

1

Pull latest

git pull origin main

2

Create branch

git checkout -b feature/x

3

Write code, commit

git add . && git commit -m "…"

4

Push branch

git push origin feature/x

5

Open Pull Request

On GitHub — get code reviewed.

6

Merge & delete

Merge on GitHub, delete the branch.
